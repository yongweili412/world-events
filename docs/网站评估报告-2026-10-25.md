## 五、新发现的问题（下一轮清单，按优先级）

### P1-A 大月归档页体积失控（本轮最明显的新问题）

2026-09 归档页实测 **3.2MB**（3,260 条全量渲染在一个 HTML），2026-10 约 4MB。单页 DOM 节点 4,000+，中低端手机会卡。且归档页比它包含的详情页还重。

- 建议：>1,000 条的月份改为"按周分组折叠"或"每月两页（上半月/下半月）"，build.py 现成框架内改动，低风险。

### P1-B 详情页没有静态 URL（SEO 最后一公里）

详情页是 `event.html?id=evt_xxx`：① 爬虫对 query string 页面收录意愿低；② title/OG 靠 JS 运行时注入，**百度/微信等不跑 JS 的爬虫只看到空壳**；③ sitemap 里没有详情页链接，5 万条内容对搜索引擎不可见。

- 建议：为最近 12 个月（约 8,000 条）生成静态详情页 `e/evt_xxx.html`（title/OG/正文全预渲染），写入 sitemap。这是把"内容资产"兑换成"可发现性"的关键一步，工作量集中在 build.py 一天左右。

### P1-C 首页索引 21MB 后台下载

index-lite.json 原始 21MB（gzip 4.3MB），首页一打开就在后台下载供搜索用。桌面无感，移动端浪费流量。

- 建议：懒加载（用户聚焦搜索框/点击筛选时才 fetch），或按年切 8 片按需加载。

### P2 慢工项（数据深度）

| 项 | 现状 | 路径 |
|----|------|------|
| 单来源 69.8% | 持平 | enrich_sources 工作流持续补证中；可对 KEEP 级事件优先补 |
| 复述速览 93.4% | 前端已隐藏 | 正确方案：对非复述条目用 LLM 生成"三要点"（kimi-k3-free 上线后成本为零，可跑） |
| 图片 3.0% | 微增 | 抓取时优先取 og:image；无图用分类色块占位 |
| .git 475M | 未动 | git filter-repo 清历史（有风险，先备份；历史已被压缩过一次但对象未 gc） |
| 访问统计 | 无 | GoatCounter 免费无 Cookie，需注册 |
